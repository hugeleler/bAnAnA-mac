设计

小香蕉分成两层。

前端是 macOS 输入法进程。它注册输入源、接收按键、画候选条、提供菜单。它不实现拼音切分和词频。

引擎在同一进程里被前端调用。引擎读方案，维护会话，返回候选和上屏串。会话跟着一次输入，引擎的生命周期跟着应用。

配置是数据，不是代码。换皮肤只换 mac.yaml 的样式键。换输入习惯只换方案和补丁。所以同一套 data/ 可以给 macOS 和 Windows 用，两端只是各读自己的皮肤文件名。

Windows 前端是另一个进程模型：文本服务进程和界面进程分开。那一页见 Windows 端。不要把 Mac 的单进程结构套到 Windows 上。
